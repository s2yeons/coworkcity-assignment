# 코워크시티 과제 — 내 사업에 맞는 비상주사무실 찾기

## 문제

코워크시티는 지점마다 지역, 사업자 유형, 과밀 여부, 건축물 용도, 인허가 업종 주소지 지원 여부, 등록 가능 업종 등의 조건이 다릅니다. 실제 지점 목록에서도 이러한 조건이 서로 다르게 제공되고 있습니다.

하지만 현재는 사용자가 자신의 **사업 업종과 사업자 유형 등의 조건을 기준으로 여러 지점을 직접 확인하고 비교해야 하기 때문에**, 자신에게 적합한 지점을 찾는 과정에 불필요한 탐색이 필요합니다.

또한 사업자등록증을 이미 보유한 사용자의 경우에도 계약 과정에서 사업자 정보를 다시 입력하거나 확인해야 하는 과정이 발생할 수 있어, **사업자등록증 정보를 활용해 입력 과정을 줄일 수 있는 방법**을 고민했습니다.

## 해결

사용자가 자신의 사업 조건을 입력하면 **이용 가능한 지점을 찾아주고, 왜 해당 지점을 추천하는지 보여주는 기능**을 추가했습니다.

`/offices/recommend`

### 1. 사업 조건으로 찾기

1. 사업 내용을 검색해 업종 선택
2. 개인 / 법인 선택
3. 지역 선택
4. 비과밀, 인허가 주소지 지원, 가격 조건 선택
5. 조건에 맞는 지점과 추천 이유 확인

지역·사업자 유형·업종과 같이 반드시 만족해야 하는 조건은 DB에서 먼저 필터링하고, 비과밀·인허가 주소지·가격과 같은 선택 조건은 점수화해 결과의 우선순위를 정했습니다.

조건을 모두 만족하는 지점이 없는 경우에는 조건을 완화했을 때 확인할 수 있는 지점 수도 함께 보여줍니다.

### 2. 사업자등록증으로 찾기

이미 사업자등록이 되어 있는 사용자는 조건을 직접 입력하는 대신 **사업자등록증을 업로드해서 시작할 수 있도록** 했습니다.

사업자등록증에서 OCR로 사업자등록번호, 대표자, 주소, 업태·종목 등을 추출하고 이를 추천 조건으로 변환해 지점 추천 과정으로 연결했습니다.

다만 사업자등록증은 표 형태의 문서이고 촬영 환경에 따라 기울기나 노이즈가 생길 수 있어, OCR 결과가 항상 정확하지 않을 수 있었습니다.

따라서 OCR 결과를 바로 사용하지 않고,

**등록증 업로드 → OCR → 필드 파싱 → 업종 매칭 → 사용자 확인·수정 → 지점 추천**

과정으로 구성했습니다.

사용자가 OCR 결과를 확인하고 직접 수정할 수 있도록 해, 인식 오류가 추천 결과에 그대로 영향을 주지 않도록 했습니다.

사업자등록번호는 형식 검사를 거친 뒤 국세청 사업자등록정보 API를 통해 실제 등록 상태를 확인할 수 있도록 구성했습니다.

실제 사업자등록증은 개인정보 문제로 테스트에 사용할 수 없어, 표준 서식을 기반으로 만든 가상 등록증 3장으로 OCR을 검증했습니다.

## 검증

* 백엔드 단위 테스트 45개
* API 통합 테스트 34개
* 390~1440px 화면에서 주요 플로우 직접 확인
* 가상 사업자등록증 3장으로 OCR 테스트
* OCR 신뢰도 89~92%, 핵심 필드 정확하게 추출

실제 서비스에 적용한다면 추천 결과 클릭률, 문의·계약 전환율, 업종 검색 실패율, 추천 결과 0건 비율 등을 기존 지점 목록과 비교해 효과를 확인할 수 있습니다.

## 데이터 및 한계

코워크시티에서 확인한 업종 정보와 지점 페이지의 구조를 참고해 데이터를 구성했습니다.

다만 실제 지점 데이터는 서비스 구조와 추천 로직을 검증하기 위한 **가상 데이터**이며, 실제 지점을 크롤링해 사용하지 않았습니다.

또한 인허가 업종과 인허가 주소지 지원 지점의 관계는 사이트에서 확인한 정보를 바탕으로 설정한 가정이며, 실제 계약 가능 여부를 의미하지 않습니다.

실제 사업자등록증을 사용한 OCR 및 국세청 진위확인까지의 전체 흐름은 개인정보 문제로 검증하지 못했습니다.

## 실행

필요한 환경:

* Node.js 22+
* Docker Desktop

```bash
npm install
npm run setup
npm run dev
```

* 추천 기능: `http://localhost:3000/offices/recommend`
* 사업자등록증으로 찾기: `http://localhost:3000/offices/recommend/registration`

사업자등록증이 없어도 화면의 가상 샘플 3장으로 OCR 기능을 확인할 수 있습니다.

## Tech Stack

| 영역             | 기술                                                |
| -------------- | ------------------------------------------------- |
| Frontend       | Next.js 16, React 19, TypeScript, Tailwind CSS v4 |
| Backend        | Node.js, Express 5, TypeScript                    |
| Database       | PostgreSQL 16, Prisma 7                           |
| OCR            | tesseract.js                                      |
| Validation     | zod                                               |
| Infrastructure | Docker                                            |

## 주요 구조

```text
사용자
  ↓
Next.js
  ↓
Express API
  ↓
Prisma
  ↓
PostgreSQL

사업자등록증 업로드
  ↓
OCR
  ↓
필드 파싱 / 업종 매칭
  ↓
사용자 확인·수정
  ↓
지점 추천
```

주요 구현:

* `backend/src/services/recommendation.ts`

  * 추천 점수 및 추천 이유 계산
* `backend/src/services/office-service.ts`

  * 지점 조회 및 필터링
* `backend/src/services/ocr.ts`

  * OCR 처리
* `backend/src/services/business-registration-parser.ts`

  * 사업자등록증 필드 추출
* `backend/src/services/industry-matcher.ts`

  * OCR 결과와 업종 매칭
* `frontend/src/components/office-recommendation/`

  * 지점 추천 UI
* `frontend/src/components/business-registration/`

  * 사업자등록증 업로드 및 결과 확인 UI
